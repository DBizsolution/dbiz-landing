How this works

For the team rebuilding this site in the CMS — how this page, the live site, and the repo fit together.

01

The live site is the spec. This repo is a working Next.js prototype, deployed at home.dbizapps.ai. The root URL serves the current design. Layout, typography, spacing, and motion should match what you see live.

02

The SVG files are the source of truth for all artwork. They live in public/assets/svg/ in the repo and are showcased below — click any filename to download the exact file the live site renders.

03

Inline the SVGs — don't reference them with <img>. The artwork uses CSS custom properties (var(--v22-…), defined in src/app/v22.5/theme.css) for every color. Those variables only resolve when the SVG markup sits in the page DOM — in Twig, e.g. {{ source('…/asset.svg') }}. Loaded via <img src>, the variables don't apply and the art renders without its colors. The previews on this page work the same way: the variable values are copied into this file's stylesheet.

04

Motion lives in the CSS, not in the files. Draw-in strokes, particle flows, and active-state recolors are selectors and keyframes in theme.css that target elements inside the inlined SVGs. The .svg files are static. When porting an animated asset, port the matching CSS with it.

05

The repo's build step is a Next.js convenience you can ignore. pnpm svg:gen compiles the .svg files into a TypeScript module (src/lib/svg-assets.ts) that React components inject inline. For the CMS build you only need the .svg files plus an inlining mechanism.

06

Copy, tokens, and brand rules. All page copy is in the React components under src/app/v22.5/. Brand color and type tokens are in src/app/globals.css; the rules for using them are in BRAND.md. The live /styleguide shows the components rendered.

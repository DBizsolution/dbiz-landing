How this works

For the team rebuilding this site in the CMS — how this page, the live site, and the repo fit together.

01

The live site is the spec. This repo is a working Next.js prototype, deployed at home.dbizapps.ai. The root URL serves the current design. Layout, typography, spacing, and motion should match what you see live.

02

This page is copy-ready. Every code block below has a Copy button, and every color chip copies its value on click. The values mirror src/app/globals.css and BRAND.md in the repo — the live source of truth.

03

The SVG files are the source of truth for all artwork. They live in public/assets/svg/ in the repo and are showcased below — click any filename to download the exact file the live site renders.

04

Inline the SVGs — don't reference them with <img>. The artwork uses CSS custom properties (var(--v22-…), defined in src/app/v22.5/theme.css) for every color. Those variables only resolve when the SVG markup sits in the page DOM — in Twig, e.g. {{ source('…/asset.svg') }}. Loaded via <img src>, the variables don't apply and the art renders without its colors. The previews on this page work the same way: the variable values are copied into this file's stylesheet.

05

Motion lives in the CSS, not in the files. Draw-in strokes, particle flows, and active-state recolors are selectors and keyframes in theme.css that target elements inside the inlined SVGs. The .svg files are static. When porting an animated asset, port the matching CSS with it.

06

Copy, tokens, and brand rules. All page copy is in the React components under src/app/v22.5/. Brand color and type tokens are in src/app/globals.css; the rules for using them are in BRAND.md. The live /styleguide shows the components rendered.

Typography

Three families, loaded once and referenced through CSS variables — never hard-code a font family. DM Sans is everything by default (UI, headings, body). DM Mono is labels, kickers, metadata and stats. Instrument Serif is an italic accent only — one phrase per section, colored orange. Never use the serif for body or UI.

1 · Load the fonts — Google Fonts (recommended for the CMS)
<link rel="preconnect" href="https://fonts.googleapis.com">
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
<link
  href="https://fonts.googleapis.com/css2?family=DM+Mono:wght@400;500&family=DM+Sans:wght@400;500;600;700;800&family=Instrument+Serif:ital@0;1&display=swap"
  rel="stylesheet">
2 · Expose them as CSS variables (drop into your global stylesheet)
:root {
  --font-sans:  'DM Sans', ui-sans-serif, system-ui, sans-serif;
  --font-mono:  'DM Mono', ui-monospace, SFMono-Regular, Menlo, monospace;
  --font-serif: 'Instrument Serif', Georgia, serif;
}

html, body { font-family: var(--font-sans); -webkit-font-smoothing: antialiased; }
Self-hosting instead? — @font-face (DM Sans is bundled in public/fonts/)
/* Only DM Sans Regular + Bold ship in public/fonts/. For DM Mono and
   Instrument Serif, add the woff2 files or keep the Google Fonts link above. */
@font-face {
  font-family: 'DM Sans';
  font-weight: 400;
  font-style: normal;
  font-display: swap;
  src: url('/fonts/DMSans-Regular.ttf') format('truetype');
}
@font-face {
  font-family: 'DM Sans';
  font-weight: 700;
  font-style: normal;
  font-display: swap;
  src: url('/fonts/DMSans-Bold.ttf') format('truetype');
}
For reference — how the repo loads them (Next.js, src/app/layout.tsx)
import { DM_Sans, DM_Mono, Instrument_Serif } from 'next/font/google'

const dmSans = DM_Sans({ subsets: ['latin'], variable: '--font-dm-sans', display: 'swap' })
const dmMono = DM_Mono({ subsets: ['latin'], weight: ['400', '500'], variable: '--font-dm-mono', display: 'swap' })
const instrumentSerif = Instrument_Serif({
  subsets: ['latin'], weight: '400', style: ['normal', 'italic'],
  variable: '--font-instrument-serif', display: 'swap',
})
